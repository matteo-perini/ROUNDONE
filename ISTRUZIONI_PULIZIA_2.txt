LIONFIT - PULIZIA 2 SAFE (19/11/2026)

SCOPO
Archiviare FUORI dalla cartella del progetto le vecchie patch: APPLICA_R..., RIPRISTINA_R..., ROLLBACK_R..., LEGGIMI di patch precedenti, manifest e cartelle PAYLOAD.
Opzionalmente archiviare anche i test storici della radice e due kit Emulator dedicati.
NON cancella nulla definitivamente. NON cambia il codice dell'app o i backend.

INSTALLAZIONE
1. Estrai i 3 file del kit nella RADICE originale di LionFit-Modern-Git (quella con package.json e src).
2. Fai doppio clic su AVVIA_PULIZIA_2_LIONFIT.cmd.
3. Seleziona 1 (anteprima). Verifica la lista.
4. Seleziona 2. Per confermare scrivi ARCHIVIA, tutto maiuscolo.
5. SOLO SE LO DESIDERI, seleziona 3 poi 4 per archiviare anche tests/ e due ambienti di test storici.
6. Per ripristinare l'ultimo gruppo spostato usa 5; ripeti 5 per ripristinare il gruppo precedente.

BACKUP
Il programma crea la cartella LionFit_ARCHIVIO_PULIZIA_2 ACCANTO a LionFit-Modern-Git, NON dentro al repository.
Ogni sessione ha data/ora, file archiviati e manifesto SHA-256 per ripristino.
Non cancellare il backup fino a quando avrai verificato tutto.

FILE TUTELATI
Non tocca src, public, Android, SVG, docs (GitHub Pages), node_modules,
backend Firebase, scripts di build, .env, dati, credenziali, regole Firestore,
LIONFIT_PREPARA_WEB_E_DOCS.cmd, README.md e codice CSS attivamente referenziato.
I file R15_ARCHIVIO.css e R19A_FOCUS_MOBILE.css sono copie d'installazione:
se trovano riferimenti nel codice attivo, il programma non li sposta.

GIT / GITHUB DESKTOP - IMPORTANTE
Quando sposti un file tracciato da Git, GitHub Desktop lo mostra come ELIMINATO.
Questo e' normale: l'archivio rimane fuori dal repository.
PRIMA DI FARE COMMIT O PUSH controlla la lista dei file eliminati e
conserva il backup; non premere Push origin alla cieca.
Se alcuni file da archiviare hanno modifiche Git non salvate il programma blocca l'operazione.

TEST
La pulizia di patch storiche non tocca i test backend.
Se archivi tests/ (opzione 4), non potrai eseguire direttamente i test in quella cartella
finche non li ripristini. La build frontend non dovrebbe dipendere da quei file.
NON vengono spostati gli ambienti test-control-emulator, test-multisport-emulator,
test-patch24-emulator e test-work-emulator, per prudenza.

DOPO LA PULIZIA
Apri VS Code nella cartella originale e verifica con npm.cmd run build.
Esegui un controllo delle funzioni principali prima di pubblicare eventuali commit.
Non e' necessario effettuare un deploy Firebase o creare un APK solo per questa pulizia.
