LION FIT — AGGIORNAMENTO LOCALE PER npm run dev CON FIREBASE PRODUZIONE
10 novembre 2026

FINALITA'
Da ora npm run dev lancia LionFit a http://localhost:5173 con Firebase del
progetto PRODUCTION, usando i profili reali, incluso l'accesso come Admin,
Coach collaboratore e Atleta. Vite resta in sviluppo con hot reload.
Non pubblica codice su GitHub, non aggiorna Firebase Rules e non sincronizza Android.

INSTALLAZIONE
1. Ferma il vecchio server (Ctrl+C).
2. Salva una copia della cartella LionFit corrente.
3. Estrai QUESTO ZIP nella stessa cartella che contiene package.json,
   sostituendo i file omonimi. La patch e' pensata per il progetto con
   PATCH 05 CORRETTA gia' applicata (10/11/2026).
4. Mantieni PRIVATO nella stessa cartella .env.production.local originale:
   non si trova nella patch e non va caricato su GitHub.
5. Apri CMD in quella cartella ed esegui:
      npm run dev
   Apri http://localhost:5173/
6. Se vuoi controllare la configurazione SENZA avviare il server:
      npm run dev -- --check
7. Per tornare al laboratorio fittizio, ora facoltativo:
      npm run dev:lab

IMPORTANTE: PRODUZIONE REALE
- La connessione Firebase e' quella REALE e le azioni autorizzate dalle
  Firestore Rules possono modificare dati REALI anche se il sito e' solo
  su localhost e non e' stato pubblicato su GitHub.
- Gli account di test, se fanno parte della palestra reale, possono
  avere accesso a documenti condivisi: calendari, schede e utenti.
- La protezione migliore per test scriventi e' una PALESTRA DI TEST
  separata anche dentro il progetto Firebase PROD, con account propri,
  oppure un progetto STAGING separato.
- Backup del CODICE non significa backup automatico del DATABASE Firestore.
  Prima dei test di cancellazione/migrazione servono backup ed export dei dati.
- Non cambiare Rules per questa patch. I controlli accesso reali restano su Firebase.
- Le variabili VITE_* sono pubbliche nel client: nessuna password o
  chiave di amministrazione deve essere inserita in esse.
- L'indicatore rosso nel CMD e il banner nell'app segnalano connessione PROD.

TECNICA
- npm run dev invoca scripts/dev-live.mjs, imposta VITE_LIONFIT_LOCAL_PROD_DEV
  soltanto nel processo locale, mode=production e NODE_ENV=development.
- isLocalProdDev() e' ammesso solo in Vite DEV e con il flag esplicito.
- La build normale npm run build e il deploy restano invariati.
- Non si cancellano i file del vecchio STAGING: non vengono utilizzati
  dal nuovo avvio quotidiano, ma possono servire per rollback/test futuri.
- non compaiono nella patch .env, file .git, keystore o credenziali.

TEST PRIMA DEL RILASCIO
- Con un account Atleta TEST, prova login, logout, cambio account,
  Home, Piano, Archivio e Prenotazioni (prima osservazione, poi scritture).
- Con Collaboratore TEST, prova salvataggio disponibilita' e controlla
  che il messaggio di conferma corrisponda ai dati persistiti.
- Con Admin TEST, controlla Gestione Atleti senza modificare utenti reali.
- Non considerare il test completato senza build Windows e controlli veri.

ROLLBACK
Il pacchetto rollback allegato ripristina i sei file prima dell'aggiornamento
(la versione PATCH 05 corretta). Il file aggiunto scripts/dev-live.mjs resta
inutilizzato dopo il rollback ed e' possibile eliminarlo manualmente.
