LIONFIT R21O — LOGIN GOOGLE IN PRODUZIONE REALE (WEB)
=====================================================
Versione incrementale, progetto Firebase app-palestra-b0b9d.
La funzione AUDIT commerciale rimane inalterata.

OBIETTIVO
- L'account Coach/Atleta esistente rimane creato con invito/email/password.
- Da Impostazioni > Sicurezza associa Google con la stessa email.
- In login appare il pulsante ufficiale Google.
- Sul backend viene verificato il Google ID token e la corrispondenza
  ESATTA del provider Google già associato all'UID Firebase esistente.
- Se non è associato, il server RIFIUTA; non crea account Firebase.
- Login con email e password continua a funzionare sempre.
- Super Admin NON può accedere attraverso la nuova funzione: usa il login attuale.
- Solo WEB desktop/browser. APK Android e PWA standalone iOS richiedono
  un collaudo OAuth specifico prima dell'attivazione di quel percorso.

NON REIMPOSTARE / NON CANCELLARE
Non disattivare Email/Password, non cancellare utenti Firebase, non modificare
Firestore Rules, non aggiornare Cloud Functions Audit, non eliminare R21N se
presente: l'installer R21O riconosce e preserva la sua interfaccia Google.

FASE 1 - FIREBASE E GOOGLE CLOUD (PRODUZIONE)
A) Firebase Console > app-palestra-b0b9d > Authentication > Sign-in method:
   abilita provider Google, conserva Email/Password attivo.
B) Authentication > Settings > Authorized domains: verifica lionfit.it
   e, se usato, www.lionfit.it.
C) Google Cloud Console stesso progetto > Google Auth Platform > Clients:
   crea o seleziona un OAuth Client ID di tipo Web application per questo login;
   autorizza le JavaScript origins https://lionfit.it e https://www.lionfit.it
   (se effettivamente usato). Copia il CLIENT ID pubblico completo.
   Non condividere il Client Secret: non serve a questa procedura.

FASE 2 - INSTALLAZIONE NEL PROGETTO WINDOWS AGGIORNATO
1. Estrai questo ZIP nella radice ESATTA:
   C:\Users\LENOVO X380\Desktop\ULTIMA\LionFit-Modern-Git
2. Apri PowerShell in quella cartella e verifica:
     cd "$env:USERPROFILE\Desktop\ULTIMA\LionFit-Modern-Git"
     Test-Path .\tools\installa-r21o.mjs
     Test-Path .\src\components\GoogleExistingSigninButton.vue
3. Esegui l'installer. Fa il backup di Settings.vue e StagingAccess.vue
   PRIMA di modificarli, senza eliminare le personalizzazioni esistenti.
     node .\tools\installa-r21o.mjs
4. Scrivi in PowerShell il CLIENT ID ottenuto da Google Cloud, es:
     $clientId = Read-Host "Incolla il Client ID OAuth Web (non il secret)"
     node .\tools\configura-r21o.mjs --prepare "$clientId"
   In modalità PREPARE entrambi i flag Google restano OFF.
   Il Client ID viene scritto anche nell'env ISOLATO del backend.

FASE 3 - BACKEND ISOLATO: DEPLOY IN PRODUZIONE
1. Verifica Node 22 nella finestra PowerShell (usa la tua cartella portatile):
     $env:Path = "$env:USERPROFILE\Desktop\node22;$env:Path"
     node --version
     firebase.cmd --version
2. Passa al backend dedicato:
     cd .\google-auth-backend
     npm.cmd install --prefix .\functions
     node --test .\functions\tests\model.test.mjs
     npm.cmd audit --prefix .\functions --omit=dev
   Se npm audit segnala vulnerabilità gravi non giustificate, non fare deploy.
3. Progetto e codebase sono volutamente isolati. Controlla che non ci
   siano funzioni esistenti col nome lfGoogleSignInExisting.
     firebase.cmd functions:list --project app-palestra-b0b9d | Select-String "lfGoogleSignInExisting"
4. Quando i controlli passano, deploy mirato (CAMBIA FIREBASE REALE):
     firebase.cmd deploy --only functions:lionfit-google-auth --project app-palestra-b0b9d
   Se chiede di ELIMINARE funzioni, interrompi con N.
5. Conferma il nuovo endpoint:
     firebase.cmd functions:list --project app-palestra-b0b9d | Select-String "lfGoogleSignInExisting"

FASE 4 - FRONTEND WEB REALE
Torna alla radice del progetto e abilita la feature SOLO dopo deploy backend:
     cd "$env:USERPROFILE\Desktop\ULTIMA\LionFit-Modern-Git"
     node .\tools\configura-r21o.mjs --enable "$clientId"
     node --test .\tests\r21o-preflight.unit.mjs
     npm.cmd run build
     .\LIONFIT_PREPARA_WEB_E_DOCS.cmd
Poi su GitHub Desktop controlla di NON includere file .env.production.local,
.env di backend, backup, cache o dist non tracciato. Commit e Push origin
secondo il tuo flusso GitHub Pages. Controlla la pubblicazione di lionfit.it.
Non è prevista alcuna anteprima locale: il collaudo è su produzione.

FASE 5 - COLLAUDO ONLINE CON UN ACCOUNT DI PROVA GIA' REGISTRATO
1. Con password entra su lionfit.it da browser desktop.
2. Vai in Impostazioni > Sicurezza > Account Google.
3. Conferma email verificata e login recente (<10 min).
4. Collega SOLO l'account Google con la stessa email dell'utente LionFit.
5. Logout. Nella pagina login usa pulsante Google; deve aprire
   ESATTAMENTE lo stesso UID e profilo palestra.
6. Controlla che compaiano le schede esistenti, poi logout e login con
   password normale: deve continuare a funzionare.
7. Prova il login Google con un account Google MAI collegato: deve essere
   negato. Firebase Authentication Users NON deve mostrare un nuovo UID.
8. Fai la stessa prova su un Coach e su un Atleta PRIMA del rilascio generale.

SE QUALCOSA NON FUNZIONA: ROLLBACK DEL SOLO GOOGLE WEB
Dalla radice progetto:
     node .\tools\configura-r21o.mjs --disable
     npm.cmd run build
     .\LIONFIT_PREPARA_WEB_E_DOCS.cmd
     (Commit e Push origin)
Le password e le funzioni Audit rimangono operative. La Cloud Function nuova
può restare online temporaneamente: non modifica né crea utenti, ma può
essere rimossa più avanti con un deploy isolato deliberato.
Non tornare indietro cancellando account o cambiando Firestore Rules.

NOTA LIMITI
Questi controlli statici NON sostituiscono la prova OAuth reale. Il server
richiede che il token sia verificato Google, che il Firebase UID esista,
che sia collegato al provider google.com con lo stesso sub, che l'utente
abbia email verificata e un profilo palestra attivo.
Il rilascio OAuth richiede anche permessi IAM per createCustomToken; se la
Cloud Function mostra errore di firma token, verifica il service account e
il ruolo iam.serviceAccounts.signBlob con il minimo privilegio.
Nessuna operazione Firebase è stata compiuta dal preparatore ZIP.
