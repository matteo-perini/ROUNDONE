PRIMA DI INSTALLARE
- Questa patch e' incrementale: NON sostituisce il progetto e NON tocca le palestre, le schede Atleta, i dati Firebase o le Cloud Functions.
- Richiede una cartella LionFit-Modern-Git gia' aggiornata fino alla R15, con il Control Center attuale.
- L'installatore riconosce i punti di codice della baseline verificata. Se uno e' diverso, SI FERMA SENZA SOVRASCRIVERE. In quel caso manda il messaggio completo, non forzare.
- Conserva la tua normale copia di sicurezza del progetto.

COSA INCLUDE
1. Panoramica Executive: vere palestre registrate e ticket open/working da letture Firestore protette, preferenze commerciali delle sole palestre caricate, data ultima verifica, accesso diretto alle funzioni esistenti.
2. Palestre & CRM: elenco paginato, filtri, scelta esente/futuro abbonamento e verifica lettura conservati, senza cambiare una riga dei metodi backend.
3. Abbonamenti: sezione preparata; NON mostra incassi inventati. Stripe live, trial e rinnovi REALI non sono ancora attivi. Sandbox Stripe preesistente invariato, ove abilitato.
4. Assistenza: ticket, risposte, gestione e notifiche push gia' esistenti, accessibili dalla sezione.
5. Stato servizi: accesso Super Admin e letture conteggi Firestore verificabili; Functions, Resend, Stripe, push, Storage e costi esplicitamente NON MONITORATI finche' non avremo fonti server verificate.
6. Utilizzo app: struttura pronta, ma nessun falso KPI; gli aggregati per palestra andranno sviluppati.
7. Sicurezza: permessi attuali confermati nel flusso, audit completo da realizzare in una fase separata.
8. Configurazione: predisposizione UI, non abilita nuovi listini o feature flag.

NOTA FONDAMENTALE SU STATO SERVIZI
Una query Firestore riuscita NON vuol dire che tutto Firebase sia sano. Un login riuscito NON dimostra l'uptime di Firebase Auth. I dati di Resend, Cloud Functions, costi Firebase, webhooks e SLA richiedono telemetria server-side: per ora sono 'Non monitorato', non 'OK'.
Nessuna richiesta di salute anonima, nessuna secret nel browser, nessuna raccolta extra di dati privati degli atleti.

INSTALLAZIONE WINDOWS (SEQUENZA ESATTA)
1. Fai backup della cartella LionFit-Modern-Git funzionante.
2. Estrai TUTTO lo ZIP direttamente dentro la cartella RADICE LionFit-Modern-Git, senza creare una cartella LionFit annidata.
3. Nella radice fai doppio clic su APPLICA_R16A.cmd.
4. Il messaggio corretto e': R16A APPLICATA CON SUCCESSO. Un backup automatico del file PlatformAdmin.vue sara' scritto nella cartella PADRE del progetto, fuori dal repository.
5. Apri il terminale di VS Code nella cartella principale e lancia:
   node --test tests/patch30-r16a-control-center.unit.mjs
   npm.cmd run typecheck
6. SOLO se i controlli terminano senza errori, esegui LIONFIT_PREPARA_WEB_E_DOCS.cmd.
7. Controlla GitHub Desktop: fai commit solo dei file src e tests modificati/creati e output docs generato, se previsto dal tuo flusso. NON committare: R16A_FILES, APPLICA_R16A.cmd, R16A_PATCH_RULES.json, backup, file .env, kit emulator, nodi di dipendenze.
8. Se la build e' riuscita, Commit/Push origin. NON fare deploy di Firebase: nessuna regola o funzione e' cambiata.
9. Test finali online: login solo account Super Admin, caricamento dei dati, passaggio tra le 8 tab, ricerca paginata palestre, ticket supporto, Stato servizi, uscita e test di accesso negato agli Admin delle palestre.
