1) Backup della tua cartella LionFit-Modern-Git.
2) Estrai TUTTO lo ZIP nella RADICE di LionFit-Modern-Git, senza una cartella doppia.
   NON contiene src/components/... direttamente: serve prima fare il backup.
3) Doppio clic APPLICA_R17B.cmd. ATTENDI "R17B APPLICATA CON SUCCESSO".
   Se viene mostrato STOP SICUREZZA, NON forzare o copiare a mano: il file e' cambiato.
   Il backup originale si trova ACCANTO alla cartella LionFit-Modern-Git,
   chiamato LionFit_R17B_BACKUP_... (non e' un errore di estrazione).
4) Apri PowerShell di VS Code nella radice ed esegui:
   node --test tests/patch30-r17b-multisport.unit.mjs
   npm.cmd run build
   Se il primo comando o la build falliscono, NON pubblicare.
5) SOLO DOPO test, controlla le Rules e pubblicale MANUALMENTE in Firebase Console:
   Firestore Database > Regole > sostituisci SOLO il blocco allowedPerson di multisport_results
   (oppure incolla il candidato solo se corrisponde esattamente alla versione live prima del fix).
   ATTENZIONE: il file candidate contiene TUTTE le Rules della produzione ricevute.
   NON usare firebase deploy generico che potrebbe cambiare altro.
6) Test con due account REALI PILOTA della STESSA palestra (meglio Emulator prima):
   A) Atleta email non verificata, autenticato: crea un altro progresso; Coach lo vede.
   B) Coach email non verificata, autenticato: crea un altro progresso; Atleta lo vede.
   C) Un Atleta NON modifica il risultato creato dal Coach e viceversa.
   D) Un atleta terzo / una palestra diversa NON vede quei risultati.
   E) Account revocato negato, super admin negato.
   F) Sessioni allenamento normali: crea solo Atleta, Coach consulta.
   G) Verifica la sincronizzazione senza reload forzato e senza doppioni.
